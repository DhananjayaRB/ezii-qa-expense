Expense Management – Receipt Entry



1. Purpose

The Receipt Entry screen allows users to record receipts for petty cash transactions received from either Parties or Employees. It helps track received amounts, adjust against advances, and maintain supporting documents.



2. Scope

This functionality is part of the Expenses / Petty Cash Management Module. The receipts recorded here will:

Update petty cash or bank balances.
Adjust advance balances (if applicable).
Store supporting documents for auditing purposes.



3. Functional Requirements

3.1 Fields and Behavior

Name* (Text)

Mandatory.
Free text input.
Receipt Type* (Radio: Party / Employee)

Mandatory.
Default: Party.
Controls the options shown in Received From dropdown.
Received From* (Dropdown)

Mandatory.
Populated dynamically based on selected Receipt Type.
Options:

Party → List of parties.
Employee → List of employees.
Open Advances (Dropdown)

Optional.
Shows open advances for the selected Party/Employee.
Remaining Advance (Textbox, Read-only)

Auto-populated based on selected advance.
Shows balance amount available.
Purpose (Text)

Optional.
Free text to capture receipt purpose.
Amount Received* (Numeric)

Mandatory.
Default: 0.
Validation: Must be greater than 0.
Payment Option* (Radio: Bank / Cashbox)

Mandatory.
If Bank selected → Bank Dropdown is shown.
If Cashbox selected → Bank Dropdown hidden.
Bank Dropdown (Dropdown)

Mandatory only if Payment Option = Bank.
Shows list of available banks.
Document Attachment (File Upload)

Optional.
Accepts file types: PDF, JPG, PNG.
Max size: 5 MB.



3.2 Buttons and Actions

Submit (Green Button)

Validate mandatory fields.
Validate numeric values.
Save record in database.
Adjust advance balance if applicable.
Upload document (if provided).
Show confirmation message: “Receipt recorded successfully.”
Clear (Orange Button)

Reset all fields to default values.
Clears any uploaded files.



4. Validation Rules

Name, Receipt Type, Received From, and Amount Received are mandatory.
Amount Received must be greater than 0.
If Payment Option = Bank, Bank Dropdown must be selected.
File upload only accepts PDF, JPG, PNG, up to 5 MB.



5. Workflow

User selects Receipt Type (Party/Employee).
User selects Received From.
If applicable, user selects Open Advance.
System displays Remaining Advance.
User enters Purpose and Amount Received.
User selects Payment Option (Bank/Cashbox).
If Bank → select Bank from dropdown.
User may upload a document as proof.
User clicks Submit.

Data is validated.
Record is saved.
Confirmation message is displayed.
User may click Clear to reset form.



6. Non-Functional Requirements

Performance: Form submission should complete in ≤ 3 seconds.
Auditability: Uploaded documents must be stored with reference to receipt ID.
Usability: Required fields should be clearly marked with *.
